# AI 厨娘：腾讯云 8005 生产部署指南

> 版本：V1.0  
> 适用日期：2026-10-14  
> 目标服务器：Ubuntu Server 24.04 LTS 64bit，Docker 27.5.1  
> 公网 IP：`YOUR_SERVER_IP`

## 1. 部署目标

本项目使用 Docker Compose 单机部署以下服务：

| 服务 | 容器端口 | 宿主机端口 | 说明 |
| --- | ---: | ---: | --- |
| `web` | 80 | **8005** | Nginx 静态前端和 API 反向代理 |
| `api` | 8000 | 不发布 | FastAPI，仅允许 Docker 内网访问 |
| `db` | 5432 | 不发布 | PostgreSQL 16 + pgvector |
| `redis` | 6379 | 不发布 | Redis，内部预留缓存 |

访问地址：

- 用户端：`http://YOUR_SERVER_IP:8005/`
- 管理后台：`http://YOUR_SERVER_IP:8005/admin/`
- 健康检查：`http://YOUR_SERVER_IP:8005/healthz`
- API 健康检查：`http://YOUR_SERVER_IP:8005/v1/healthz`

> 当前是 HTTP + IP 访问。微信小程序体验版或正式版使用前，需要准备已备案域名并配置 HTTPS；不要把 `8000`、`5432`、`6379` 加入安全组。

## 2. 服务器资源建议

当前规格为 2 核 CPU、2GB 内存、50GB SSD、4Mbps 带宽、300GB/月流量。Compose 已设置保守资源上限：

- `web`：0.50 CPU / 192MB
- `api`：1.00 CPU / 768MB
- `db`：0.65 CPU / 512MB
- `redis`：0.25 CPU / 128MB

首次部署前建议增加 2GB swap，防止 Docker 构建后端镜像或数据库迁移时触发 OOM：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

检查系统：

```bash
cat /etc/os-release
uname -m
nproc
free -h
df -h /
docker --version
docker compose version
```

## 3. 腾讯云安全组

建议仅开放：

| 方向 | 协议 | 端口 | 来源 |
| --- | --- | ---: | --- |
| 入站 | TCP | 22 | 办公网固定 IP，尽量不要 `0.0.0.0/0` |
| 入站 | TCP | 8005 | 演示期间可限制为办公网 IP；确需公网访问再放开 |
| 出站 | ALL | ALL | 默认放通，用于拉取镜像和访问模型 API |

禁止开放 `8000`、`5432`、`6379`。应用对外只经 Nginx 的 `8005`。

## 4. 首次准备

在服务器执行：

```bash
sudo mkdir -p /opt/ai-cook
sudo chown -R "$USER":"$USER" /opt/ai-cook
cd /opt/ai-cook
```

将代码放到 `/opt/ai-cook`，并确认以下文件存在：

```text
docker-compose.yml
docker-compose.prod.yml
Dockerfile.web
backend/Dockerfile
backend/docker-entrypoint.sh
nginx/nginx.conf
backend/data/HowToCook/dishes/
backend/assets/recipe_covers/
backend/.env
.env.production
aicook-web.tar 或 aicook-web.tar.gz
```

`backend/.env` 含 LLM/VLM/语音配置，`.env.production` 含数据库和管理员凭据，均不得提交 Git。

生成生产密钥：

```bash
openssl rand -hex 24
openssl rand -hex 32
```

复制模板并编辑：

```bash
cp .env.production.example .env.production
chmod 600 .env.production
cp backend/.env.example backend/.env
chmod 600 backend/.env
```

至少填写：

- `.env.production`：`WEB_PORT=8005`、`PUBLIC_IP=YOUR_SERVER_IP`、`WEB_IMAGE`、`DB_PASSWORD`、`ADMIN_PASSWORD`、`ADMIN_JWT_SECRET`
- `backend/.env`：`LLM_API_KEY`、真实视觉/语音 Provider 的 API Key；不要把线上能力留在 `mock`

## 5. 本地构建前端镜像

2GB 服务器不执行两套前端的 Node 构建。以下命令在本地 Windows PowerShell 执行：

```powershell
Set-Location D:\Code_Work\AI_Cook
$tag = "aicook-web:20261014"
docker build -f Dockerfile.web -t $tag .
docker save $tag -o aicook-web.tar
```

将 `aicook-web.tar` 上传到服务器 `/opt/ai-cook/`，并让 `.env.production` 的 `WEB_IMAGE` 与 tag 完全一致：

```text
WEB_IMAGE=aicook-web:20261014
```

如果本地 Docker 不可用，需先在本地安装 Docker Desktop 或使用 CI 构建；不要改成在 2GB 服务器上执行前端构建。

## 6. 服务器部署

在服务器执行：

```bash
cd /opt/ai-cook
docker load -i aicook-web.tar

docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml config --quiet

bash scripts/deploy.sh --check
bash scripts/deploy.sh --seed
```

`--seed` 只在首次部署或明确需要补种子数据时执行。已有业务数据的更新部署使用：

```bash
bash scripts/deploy.sh
```

查看服务：

```bash
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml ps
```

预期只有 `web` 显示 `0.0.0.0:8005->80/tcp`；不应出现宿主机 `8000`、`5432` 或 `6379` 映射。

## 7. 上线验证

服务器本机执行：

```bash
curl -fsS http://127.0.0.1:8005/healthz
curl -fsS http://127.0.0.1:8005/v1/healthz
curl -I http://127.0.0.1:8005/
curl -I http://127.0.0.1:8005/admin/
```

公网或浏览器访问：

```text
http://YOUR_SERVER_IP:8005/
http://YOUR_SERVER_IP:8005/admin/
```

检查端口：

```bash
sudo ss -ltnp
```

只应看到 SSH 和 `8005` 等必要监听；应用容器内部的 8000 不应出现在宿主机监听列表。

## 8. 常用运维命令

```bash
cd /opt/ai-cook
COMPOSE="docker compose --env-file .env.production -f docker-compose.yml -f docker-compose.prod.yml"

# 查看状态
$COMPOSE ps

# 查看全部日志
$COMPOSE logs --tail=200

# 查看 API 日志
$COMPOSE logs -f --tail=200 api

# 重启单个服务
$COMPOSE restart api

# 停止并保留数据卷
$COMPOSE down

# 重新启动
$COMPOSE up -d

# 查看资源
docker stats --no-stream
free -h
df -h /
```

PowerShell 不支持上面的 shell 变量写法；在 Windows 端请直接重复完整的 `docker compose` 命令。

## 9. 更新与回滚

更新前保留当前前端镜像 tag：

```bash
docker image ls aicook-web
```

加载新镜像、修改 `.env.production` 的 `WEB_IMAGE` 后：

```bash
docker load -i aicook-web-new.tar
bash scripts/deploy.sh
```

回滚只需把 `WEB_IMAGE` 改回上一版本 tag，再执行：

```bash
bash scripts/deploy.sh
```

数据库迁移已经执行后，不保证应用镜像可以无条件回滚；回滚前先确认 Alembic 迁移是否向后兼容。

## 10. 数据备份

数据库备份到宿主机：

```bash
mkdir -p /opt/ai-cook/backups
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml \
  exec -T db pg_dump -U postgres -d aicook \
  | gzip > "/opt/ai-cook/backups/aicook-$(date +%Y%m%d-%H%M%S).sql.gz"
```

封面和语料在 `backend/assets`、`backend/data`，上传图片在命名卷 `uploads`。数据库备份和上传文件备份应定期复制到服务器之外；50GB 系统盘不适合长期保存大量备份。

恢复数据库前停止 API，避免业务请求写入：

```bash
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml stop api
gunzip -c /opt/ai-cook/backups/backup.sql.gz | \
  docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml exec -T db \
  psql -U postgres -d aicook
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml start api
```

## 11. 常见故障

### `8005` 无法访问

依次检查：

```bash
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml ps
sudo ss -ltnp | grep 8005
sudo ufw status
```

同时确认腾讯云安全组入站 TCP `8005` 已放行。

### API 容器反复重启

```bash
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml logs --tail=200 api
```

重点看数据库连接、Alembic 迁移、`backend/.env` 和外部模型配置。不要直接删除 `pgdata`。

### 前端容器启动失败

```bash
docker compose --env-file .env.production \
  -f docker-compose.yml -f docker-compose.prod.yml logs --tail=200 web
docker run --rm aicook-web:20261014 nginx -t
```

### 磁盘或内存不足

```bash
df -h
free -h
docker system df
docker stats --no-stream
```

只清理明确无用的悬空镜像，不要删除正在使用的镜像、命名卷或生产容器：

```bash
docker image prune
```

## 12. 禁止操作

```bash
docker compose down -v
docker volume prune
rm -rf /opt/ai-cook/backend/data
rm -rf /opt/ai-cook/backend/assets
```

这些操作可能删除数据库、语料或封面数据。生产环境需要删除数据时，必须先完成备份并单独确认。
