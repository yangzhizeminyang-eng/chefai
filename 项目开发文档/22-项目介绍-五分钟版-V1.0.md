# AI 厨娘项目介绍

面试官您好，我这个项目叫 AI 厨娘，是一个面向家庭做饭人群的智能烹饪助手。



家庭做饭有个很实际的矛盾：冰箱里有食材，却不知道做什么；网上菜谱写得完整，却不一定适合。尤其是过敏，出了问题还是用户自己承担。



所以我把这件事拆成一条完整流程：用户选食材或发起请求，系统先过安全闸门，**再做菜谱召回与硬过滤**；用户选定菜谱后，可以看详情、分步烹饪、查营养，并把库存和烹饪反馈继续沉淀下来。



## 第一块 · 推荐与食品安全

**它要解决的问题是：推荐不能只看“像不像”，还得先保证“能不能吃”。**

技术栈上，编排用 LangGraph 主图加推荐子图，数据层是 PostgreSQL 加 pgvector，**过敏原和饮食禁忌**直接写成 SQL 布尔条件，挂在检索和排序中间。

实现了食材别名归一，再用覆盖率、文本、向量三路召回，过完 SQL 硬过滤再进 7 因子排序，按三档取前 8 条；候选不够就如实说明。



## 第二块 · 检索与评测

**它要解决的问题是：用户说法不一定和菜谱标题一致，检索结果还必须能解释。**

菜谱结构化入库，一条菜谱一条向量，嵌入走智谱 embedding-3、2048 维，存进 pgvector。实现了三路混合召回，**结果带来源和引用 ID 可跳转**。全部放进 Eval：意图 1.0，检索 Hit@3 0.96、MRR 0.93，引用可追溯 1.0，门禁 PASS。



## 第三块 · 可控的 Agent 主链路

**它要解决的问题是：模型可以帮忙理解请求，但不能做决定**

技术栈上，编排用 LangGraph。Supervisor 只输出意图标签，走哪个节点由固定字典决定，所有路径必须过出口闸门才能返回；**节点耗时、风控判定、未执行节点**都写进 trace，按 request_id 可回查。

因此它既能跑通完整流程，也能回答“为什么给这个结果、为什么这次被拦”。





这个项目明确了AI功能的边界：模型适合处理语言和提供候选，安全、权限必须由系统规则兜住。
