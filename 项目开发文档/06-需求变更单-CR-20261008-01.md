## 二、变更内容详述

### 2.1 新增能力

| 项 | 说明 |
| --- | --- |
| **用户价值** | 解决「有食材、没灵感」——补上「推荐」之外的第二种内容来源 |
| **核心机制** | **受约束生成**：「能不能配」由**规则引擎**判定（确定性、可审计、可回滚），「怎么表达」才交给 LLM |
| **四条创新原则** | ① **安全约束**（硬门，不满足即拒绝生成）② **物理化学约束**（质地 / 含水量 / 风味 / 耐热性 / 吸油性适配）③ **工艺约束**（技法白名单 + 用量必须量化）④ **可解释约束**（必须给出创新依据） |
| **闭环** | 生成 → 采纳 → 我的创新菜 → 烹饪引导 → 评分反馈 → **规则权重回流** → 高频优质搭配进入候选池 → 后台**专家双签审核** → 可升格为正式菜谱 |

## 三、影响分析

### 3.1 合规影响（🔴 最高优先级）

| # | 影响 | 结论 |
| --- | --- | --- |
| 1 | 触碰 **RL-1**（不得提供中毒风险指导） | **已设计规避**：安全前置校验为「允许 / 不允许」判定，命中 11 类高危即**拒绝生成** |
| 2 | 触碰 **RL-2**（不得输出安全承诺） | **已设计规避**：强制「AI 创新菜 · 未经人工审核」标识 + 固定免责话术（TXT-O03 / O04） |
| 3 | 触碰 **RL-7 / RL-11**（不得医疗 / 功效宣称） | **已设计规避**：「食材性质」**只用可观测的烹饪科学属性**，**严禁中医性味 / 寒热温凉 / 归经 / 食疗功效类表述**（见待确认项 Q11） |
| 4 | 触碰 **RL-9**（不得法定营养声称） | **已设计规避**：走同一套输出侧闸门 |
| 5 | 触碰 **RL-10**（不得食物相克） | **已设计规避**：搭配规则中「禁止搭配」须有科学依据，**不得收录相克类伪科学** |
| 6 | 业务风险 **R-5**（模型幻觉编造菜谱 / 用量） | **已设计规避**：用量由配比模板生成，「出现适量即判不合格」；创新菜**不进默认推荐**（检索分区隔离）、**不进正式菜谱库**；仅入**用户私有向量分区** |
| 7 | **RL-19**（图片素材版权） | ⚠️ **未决**：创新菜成品图是否用 AI 生成 → **需评估**（待确认项 Q16） |

> ✅ **总体结论：合规风险可控**，前提是 7 项待确认项（尤其 Q11 / Q12 / Q14）全部按建议口径确认。
