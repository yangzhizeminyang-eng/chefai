## 1. 问题诊断（实测证据）

### 1.1 现象

首页两个入口卡「今天吃什么」与「时令吃什么」点击后**落到同一页面、同一形态**，与卡片文案承诺不符：

| 入口卡 | 卡片文案（现状） | 现跳转目标 | 实际发生 |
| --- | --- | --- | --- |
| 今天吃什么 | 选食材，三档推荐 | `/select` | 进入 W-01 手选食材页 |
| 时令吃什么 | 应季食材优先推荐 | `/select?seasonal=1` | **同样进入 W-01，`seasonal` 参数被忽略** |

### 1.2 代码级证据（逐条可复核）

| # | 证据 | 位置 | 结论 |
| --- | --- | --- | --- |
| E1 | 入口配置 `to: '/select?seasonal=1'` | `HomeView.vue` L135-142 | 时令入口仅"多带了个参数" |
| E2 | 页面只读 `route.query.q`，无任何 `seasonal` 分支 | `SelectIngredientView.vue` L249（`?q=` 消费）、L204（清 query） | **`seasonal` 从未被消费** |
| E3 | 全仓 `seasonal` 命中仅 1 处（HomeView 生产端） | `web-stage1/src` 全量 grep | 无消费方，参数为空转 |
| E4 | 首页接口返回 `seasonal_categories`，前端无任何引用 | `backend/app/api/v1/home.py` L200-213 / L295 | **当季数据为死数据** |
| E5 | 推荐主接口请求体 `ingredients: list[RecommendIngredient] = Field(min_length=1)` | `backend/app/schemas/recommend.py` | **不存在"零输入直出推荐"通路** |
| E6 | 时令类别为中文名（根茎类 / 叶菜类 / 瓜果类…），食材接口 `category` 仅接受 10 类编码（veg/meat/seafood/egg_milk/soy/staple/seasoning/dry/frozen/other） | `home.py` L70-83 vs `ingredients.py` L22 / `models/ingredient.py` L43 | **两套口径不可对接** |

### 1.3 根因

1. **入口语义与落点能力错配**：文案承诺"推荐"（决策输出），落点却只有"输入"（选食材），把"选择题"交给了不知道怎么选的人。
2. **时令能力只做了半截**：后端发了当季类别、前端从未接；即便接了，类别口径也对不上。
3. **缺"零输入"推荐通路**：所有推荐都必须先有 `ingredients ≥ 1`，导致"今天吃什么"在架构上只能退化为"去选食材"。

## 4. 两入口定位重定义

核心原则：**两个入口解决的是两种完全不同的"不知道"**。

| 维度 | 今天吃什么 | 时令吃什么 |
| --- | --- | --- |
| 用户此刻的状态 | 手边有事可做，但**决定不了做什么**（决策疲劳） | 不急着解决库存，想**跟着季节吃**（场景驱动） |
| 真正的问题 | "替我做决定" | "现在这时候该吃什么" |
| 输入 | **零输入**（可选叠加：冰箱现有食材） | **零输入**，季节为唯一隐含输入 |
| 输出形态 | 3–6 道可执行候选 + **换一换** | 当季食材清单（可一键转推荐）+ 当季菜谱列表 |
| 失败兜底 | 「去选食材，拿更准结果」 | 「看看全部食材库」 |
| 与 W-01 的关系 | **不强制**先去 W-01（可跳出） | 提供"用当季食材去推荐"按钮 → 进 W-01 且预置筛选 |
| 与 W-02 的关系 | 复用 W-02 卡片与硬过滤链路（**风控不绕过**） | 同上 |

**一句话差异**：
> 「今天吃什么」= 我给你答案（零输入直出）；「时令吃什么」= 我给你这个季节的素材与菜（季节驱动）。

## 5. 方案对比与选型

### 方案 A —— 最小改动（仅修偏离 + 对齐文案）

- 做法：`/select` 真正消费 `seasonal`（预置当季分类筛选）；「今天吃什么」desc 改为"选食材，三档推荐"并保持落 W-01。
- 成本：极低（前端 0.5 人日）。
- 风险：无（属返工对齐）。
- **致命缺陷**：用户核心诉求未解决 —— 两入口仍落同一页面，差异仅为"筛选预设"；"今天吃什么"仍要求用户先做选择题。

### 方案 B —— 双落点重构（推荐）

- 做法：
  1. **今天吃什么 → 新增 `/today`（今日推荐决策页）**：零输入直出 3–6 道候选 + 「换一换」；卡片复用 W-02；底部兜底「去选食材，拿更准结果」→ W-01。
  2. **时令吃什么 → 新增 `/seasonal`（时令页）**：上部"当季食材"清单（可多选）＋ 下部"当季菜谱"列表；按钮「用这些时令食材去推荐」→ W-01 预置选中 / 或直接进 W-02。
  3. 后端新增**零输入推荐**能力（放开 `ingredients` 下限 + `mode` 语义）与**时令过滤**口径（见 §8）。
- 成本：前端 2.5 + 后端 2 + 测试 1 + 文档同步 0.5 ≈ **6 人日（估算）**。
- 风险：中 —— 涉及接口契约变更与可能的数据字段变更；需 CR 与 Q-49~Q-52 确认。
- 优点：真正兑现入口文案；语义分化清晰；复用既有三档卡片与**布尔硬过滤**链路，风控不退化。

### 方案 C —— 引入节气/农时数据 + 「今日菜单」（三餐组合）

- 做法：接入节气/农时数据源，生成"今日菜单"（早/午/晚/加餐组合）。
- 成本：高（外部数据接入 + 组合推荐 Agent）。
- 风险：高 —— 阶段一无数据源；**极易滑向养生/功效话术，触碰医疗宣称与法定营养声称红线**。
- 结论：**本期不做**，记入阶段二路线（触发条件：甲方提供合规农时数据源且完成合规评审）。

### 选型结论

> **推荐方案 B**。同时明确：**方案 A 中的"修正时令偏离"是无论如何都要做的返工项**（独立于 B/C），建议先随下次提交修掉，避免"参数空转"继续留在仓库。

| 方案 | 实现成本 | 复杂度 | 用户体验 | 合规风险 | 综合评价 |
| --- | --- | --- | --- | --- | --- |
| A | 低 | 低 | 中（诉求未解） | 无 | 仅作返工基线，不单独交付 |
| **B** | 中 | 中 | **好** | 低（复用既有风控链路） | ✅ **推荐** |
| C | 高 | 高 | 好 | **高** | ❌ 本期不做，列阶段二 |

## 6. 推荐方案 · 交互细化

### 6.1 `/today` 今日推荐决策页（对应入口：今天吃什么）

**页面目标**：让"不想做选择"的用户在 **1 次点击内拿到可执行候选**。

**页面结构（自上而下）**

| 序 | 区块 | 内容 |
| --- | --- | --- |
| 1 | 标题区 | 「今天吃什么」+ 副标题「没想好？先看这几道」（**不使用绝对化/疗效类表述**） |
| 2 | 候选区 | 3–6 张推荐卡（复用 W-02 卡片：菜名/图/耗时/难度/热量/设备标注） |
| 3 | 主操作 | 「换一换」（重新取一批候选，**同一批内不重复**） |
| 4 | 兜底操作 | 「我有食材，去选食材」→ W-01；「用冰箱里的食材」→ 若有库存则预置选中后进 W-02 |
| 5 | 说明条 | 「未选食材时按可执行性与时令给出候选，选择食材后结果更准」 |
| 6 | 过敏原提示 | 未建档/未设过敏原 → 复用首页黄条文案（BR-14），**不静默** |
| 7 | 底部 | 常驻免责小字（DisclaimerBar） |

**关键交互规则**

| # | 规则 |
| --- | --- |
| 1 | **零输入可直接出结果**，不得弹窗索要食材（这是本页存在的意义） |
| 2 | 「换一换」节流：请求进行中置灰；连续 3 次未见新结果 → 提示「试试放宽条件或去选食材」，不无限空转 |
| 3 | 零输入态**不展示"覆盖率"列**（无语义），档位改为耗时口径（见 §6.3 规则 3） |
| 4 | 过敏原 / 忌口 / 难度 / 设备**硬过滤照常生效**，零输入绝不等于放宽风控 |
| 5 | 点击卡片 → W-03 菜谱详情（保持既有链路） |
| 6 | 三态：加载=骨架卡+「正在为你挑今天这顿」；空=说明原因 + 「去选食材」；异常=el-alert + 重试 |

### 6.2 `/seasonal` 时令页（对应入口：时令吃什么）

**页面目标**：回答"这个时节该吃什么"，并把用户自然引到推荐链路。

**页面结构（自上而下）**

| 序 | 区块 | 内容 |
| --- | --- | --- |
| 1 | 标题区 | 「时令吃什么」+ 副标题「{当前月份}月 · 当季食材」（月份来自服务端，不前端硬算） |
| 2 | 当季食材区 | 当季食材卡/标签（多选，可全选）；每项显示名称 + 分类 |
| 3 | 主操作 | 「用这些去推荐」→ 预置选中进 W-01（保留可编辑）或直接进 W-02 |
| 4 | 当季菜谱区 | 当季菜谱列表（复用 W-02 卡片，来源标注与时令依据） |
| 5 | 兜底操作 | 「看看全部食材库」→ W-01 全部态 |
| 6 | 说明条 | 「当季信息仅为食材供应参考，不代表食材品质或营养优劣」 |
| 7 | 底部 | 常驻免责小字 |

### 6.3 双页共通规则（含对既有 3 档语义的处理）

| # | 规则 |
| --- | --- |
| 1 | 两页均**必须**经过输入侧 + 输出侧双重风控；一票否决 → 跳 W-05（控制流短路，不"标记后丢弃"） |
| 2 | 两页均**必须**展示免责小字；时令页另加"当季≠更优"客观陈述说明条 |
| 3 | **零输入态的档位口径**（重要）：W-02 既有三档（现在就能做 / 差 1–2 样 / 需要多买几样）以"食材覆盖率"为前提，零输入下不成立。零输入态改用**耗时口径**：`≤15 分钟` / `15–30 分钟` / `需备料`，并在页面显式说明口径来源；**此条属对 PRD 三档定义的补充，须写入 CR 并同步 03-UI 清单** |
| 4 | 未建档用户：两页均保留"未设置过敏原"黄条，引导去建档，**不阻断浏览** |
| 5 | 「换一换」与"当季菜谱"均须**告知候选来源**（`rank_reasons` 展开），与 W-02 一致 |
| 6 | 不得出现"最"、"第一"、"顶级"、"增强免疫力"、"养生"、"排毒"等绝对化/功效用语 |

### 6.4 首页入口修正（附带的非变更项）

| 项 | 现状 | 修正 |
| --- | --- | --- |
| 时令入口跳转 | `/select?seasonal=1`（参数空转） | 改为 `/seasonal`（新增页） |
| 今天吃什么跳转 | `/select` | 改为 `/today`（新增页）；若 Q-49 结论为"不改定位"，则退回"仅对齐 desc 文案" |
| 主/次入口层级 | 6 张等权卡 | 按 PRD §6.3 恢复层级：今天吃什么（主卡，占 2 格）+ 拍一下冰箱（次主），其余 4 张为次级 |

| --- | --- |
| **RL-2 风控不可跳过** | 零输入态**不是**放行态：仍走输入侧 + 输出侧风控；`/today`、`/seasonal` 的每次请求均需过闸 |
| **RL-3 不做可食性判定** | 时令页只展示"供应时令"，**不得**出现"当季更新鲜/更安全"等判定性、比较性表述；文案固定收口"当季信息仅为食材供应参考" |
| **RL-4 风控失败→保守模式** | 零输入推荐若风控不可用，同样进入 `safe_mode`，**不得**直连模型给候选 |
| **过敏原 = 布尔硬过滤（DB 层）** | 「今天吃什么」零输入默认过滤仍读取档案过敏原/忌口；**不得**因"没提供食材"而降级为仅提示 |
| **RL 内容宣传（法定营养声称/功效/绝对化）** | 双页禁止"低脂/无糖/高蛋白"等法定声称与"养生/排毒/增强免疫力"；时令页**不得**做食疗暗示 |
| **RL 医疗宣称** | 时令页禁止"应季防病/调理"类表述；「今天吃什么」的个性化理由只能基于口味/难度/耗时/库存，不涉健康结论 |
| **免责声明固定附着** | 双页底部常驻 DisclaimerBar；时令页额外加"当季≠更优"说明条 |
| **识别结果不入库原则** | 本方案不涉及识别的改动；「用冰箱里的食材」沿用既有库存（已确认数据），不得绕过确认 |

## 9. 异常与边界清单

| # | 场景 | 期望行为 |
| --- | --- | --- |
| 1 | 零输入推荐返回 0 条 | 说明原因 + 「去选食材」/「用冰箱里的食材」，**不编造填充** |

## 10. 验收标准（Given / When / Then）

| 编号 | 验收项 | 验收标准 |
| --- | --- | --- |
| AC-01 | 今天吃什么 · 零输入直出 | Given 用户未选任何食材；When 点击「今天吃什么」；Then 进入 `/today` 并返回 **3–6 道**候选，全程无"请先选择食材"拦截 |
| AC-02 | 今天吃什么 · 换一换 | Given 已有候选；When 点击「换一换」；Then 结果刷新且与上一批**不重复**（同批去重）；请求中按钮置灰 |
| AC-03 | 今天吃什么 · 风控不绕过 | Given 档案中登记了过敏原；When 零输入出候选；Then 含该过敏原的菜谱**不出现**（可经"被过滤清单"取证其被过滤原因） |
| AC-04 | 时令吃什么 · 与入口文案一致 | Given 当前月份映射存在；When 点击「时令吃什么」；Then 进入 `/seasonal` 并展示**当季食材区 + 当季菜谱区**（不再进入选食材页） |
| AC-05 | 时令吃什么 · 转推荐 | Given 时令页已展示当季食材；When 点击「用这些去推荐」；Then 进入推荐链路且食材已预置，结果可编辑返回 |
| AC-06 | 口径一致性 | Given 进入任一零输入页面；When 查看分组标题；Then 显示为**耗时口径**且在页面显式说明口径来源（不再出现无法成立的"覆盖率"档位） |
| AC-07 | 免责与合规 | Given 进入任一新页面；Then 底部常驻免责小字可见；时令页额外可见"当季≠更优"说明条；页面无绝对化/功效用语（违禁词自查通过） |
| AC-08 | 时令参数不再空转 | Given 首页时令入口；Then 全仓 grep 无 `seasonal` 空转参数，路由指向唯一目标页 |
| AC-09 | 异常兜底 | Given 接口失败/返回 0 条；Then 展示明确原因 + 下一步入口，**不白屏、不编造** |
| AC-10 | 主次入口层级 | Given 首页；Then 「今天吃什么」视觉权重高于其余入口卡（对齐 PRD §6.3 主/次主划分） |
