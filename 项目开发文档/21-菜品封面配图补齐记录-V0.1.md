## 1. 背景与目标

推荐结果卡片与菜谱详情页中，部分菜品封面缺失，前端回落为「暂无实拍」占位图，造成卡片视觉参差、CTR 受损。

本次目标：为全部缺图菜品补齐成品图，并**在视觉风格、构图、色调上与现有封面保持统一**，使其在网格排列中不产生割裂感。

## 2. 缺图盘点

封面资源不对应语料目录，而是由 `corpus_howtocook.copy_cover()` 复制到
`backend/assets/recipe_covers/{md5(菜名)[:12]}{ext}`，接口侧由
`resolve_recipe_cover_url()` 依据文件是否存在**动态补全** `cover_image_url`。

因此盘点口径为：拉取 `/v1/recipes` 全量 → 逐条核对 `cover_image_url` 是否为空。

| 项 | 数量 |
| --- | --- |
| 数据库在架菜谱 | 390 |
| 本次盘点前已有封面 | 370 |
| **本次补齐** | **20** |
| 补齐后覆盖率 | **390 / 390 = 100%** |

> 说明：语料 md 为 373 篇，数据库 390 道，差额为早期内置演示菜谱（id 1–45 段），其本身无对应语料 md，故一并按统一风格生成。

## 3. 风格基准（从现有封面逆向提取）

对 `recipe_covers` 全量做尺寸与视觉分析，主模态为 **1536×1024（3:2 横构图，187 张）**，据此锁定统一规范：

| 维度 | 规范 |
| --- | --- |
| 画幅 | 3:2 横构图，输出 1536×1024 |
| 机位 | 三脚架斜俯拍，仰角约 40°，主体居中占画面约 65–75% |
| 台面 | 浅色天然橡木纹台面，铺满背景、无墙面/窗框等环境元素 |
| 器皿 | 白色釉面陶瓷盘 / 深口白瓷碗；炖菜类用深色铸铁锅；饮品用透明玻璃杯 |
| 光线 | 左上方向柔和自然窗光，柔化阴影，明亮通透，无硬高光 |
| 色调 | 干净中性偏暖，真实色彩，适度高光油润感 |
| 构图 | 大量负空间，浅景深，主体清晰 |
| 禁用 | 文字、水印（生成端固有标记除外）、人物、手、筷子/勺子等道具 |
| 文件 | JPEG q86 progressive，约 180–370KB |

## 4. 执行路径

| 环节 | 说明 |
| --- | --- |
| 通道 | 可灵 AI 可用额度为 0，无法提交；经用户确认改用 **WorkBuddy 内置生图通道** |

| 接入 | **零代码改动、零数据库迁移**：接口按文件名哈希自动识别并补全 `cover_image_url` |

## 7. 合规风险（需甲方确认）

🔴 **`cover_image_source` 标注与实际不符**

`recipes.py:288` 中该字段为硬编码：
```python
"cover_image_source": "HowToCook 语料配图（Unlicense 公有领域）" if cover_image_url else None
```
只要 `cover_image_url` 非空即标注为「Unlicense 公有领域」，无法区分来源。本次 20 张为 **AI 生成图**，沿用该标注等于对 AI 生成内容作出错误的版权归属声明，涉及项目「图片版权 / 开源许可」红线，建议在阶段二前处置。

可选处置（按侵入度递增）：
- **A**：`recipe_covers` 下增加来源约定（如 `{hash}.ai.jpg` 或并列 `provenance.json`），`resolve_recipe_cover_url()` 读约定返回对应 source 文案。
- **B**：`recipes.cover_image_source` 落库为独立列，种子脚本写入真实来源。
- **C**：前端弱化该标注为中性文案「图片来源见菜谱说明」，待来源体系完善后再细分。

其余：生成图为食物静物、无人物与品牌标识，不涉及肖像权与商标风险；菜名与食材描述均取自现有语料，未新增功效/医疗宣称。
