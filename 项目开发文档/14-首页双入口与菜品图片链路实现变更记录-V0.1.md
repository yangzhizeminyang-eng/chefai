## 1. 变更概要

按《12》《13》两份设计方案完成实现与验证，范围：

| 模块 | 变更 |
| --- | --- |
| 首页双入口 | 「今天吃什么」→ 新页 `/today`（零输入直出 3–6 道 + 换一换 + 耗时口径分组）；「时令吃什么」→ 新页 `/seasonal`（当季食材多选 + 当季菜谱 + 一键转推荐）；`/select?seasonal=1` 空转参数清理 |
| 菜品图片链路 | HowToCook 语料图片（Unlicense 公有领域）经 seed 导入 `backend/assets/recipe_covers/` → 静态服务 `/v1/media/recipe-covers/` → 推荐/详情接口新增 `cover_image_url` → 前端卡片与详情成品图；无图自动回落程序化占位封面（色板 + 🍳 + 菜名 + 「示意图」角标） |

## 2. 甲方拍板记录（Q-55 破例）

《13》§5 方案 C（复用 HowToCook 语料图片）原受项目自定规则 `05-V1.1 §5.6`「语料图片禁止复用」限制，属阻塞级法务问题 Q-55。**2026-10-12 甲方以指令明确确认复用语料图片**，破例生效；详情页按 RL-19 落地来源标注「图片来源：HowToCook 语料配图（Unlicense 公有领域）」。该仓库 LICENSE 实测为 Unlicense（公有领域）。

## 3. 后端变更

| 文件 | 变更 |
| --- | --- |
| `app/seed/corpus_howtocook.py` | 图片定位（同名图 → 成品.jpg → 目录首图）+ md5 安全文件名复制 + `cover_image_url` 填充；**存量回填**：seed 幂等重跑自动补齐历史 NULL 封面 |
| `app/main.py` | 挂载 `StaticFiles` 至 `/v1/media/recipe-covers`（`backend/assets/recipe_covers/`，与 24h 清理的 `uploads/` 硬隔离） |
| `app/api/v1/day_menu.py`（新增） | `POST /v1/recommend/day-menu`：零输入直出，`exclude_ids` 支持换一换；复用既有 `hard_filter`（过敏原/忌口/难度/设备布尔硬过滤不绕过），无 LLM 参与，不做幂等缓存 |
| `app/api/v1/seasonal.py`（新增） | `GET /v1/seasonal`：12 月当季食材白名单（261 条全部与 seed 库核对命中）+ 当季菜谱召回（主料命中 + 同款硬过滤 + 耗时排序 ≤8）；异常降级 HTTP 恒 200 |
| `app/api/v1/router.py` | 注册 day_menu / seasonal 子路由 |
| `app/schemas/recommend.py` | `RecommendResultItem` 新增 `cover_image_url: str \| None`（向后兼容） |
| `app/api/v1/recommend.py` | 展示适配层批量加载封面字段 |
| `app/api/v1/recipes.py` | 详情响应新增 `cover_image_url` + `cover_image_source`（来源标注） |

**未改动**：`home.py`（`seasonal_categories` 保留）、`POST /v1/recommend` 既有契约与 graph 编排、风控引擎、双闸门、识别/库存/会员链路。

## 6. 遗留与阶段二事项

- 图片压缩（单张 ≤120KB 目标，NFR-2.6）与后台上传能力（admin-web）按《13》§12 阶段二排期；阶段一图片直接复制原文件。
- 当季食材白名单为静态常量（阶段二可迁移 DB `season_tags`，《12》G1 方案 b）。
- 「换一换」连续 3 次同批的文案提示已落地，批次池穷尽极端场景（exclude 全库）由空态兜底承载。
