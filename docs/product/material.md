# Material: AI 厨娘·智能烹饪助手（项目答辩）

## 1. Overview

- **产品定位**：面向**家庭做饭人群**的智能烹饪助手，覆盖「食材 → 推荐 → 分步引导 → 营养 → 库存 → 会员」全链路。
- **核心形态**：多智能体（LangGraph 编排）＋ 食品安全风控 ＋ 个性化推荐，三端同源（Web / 微信小程序 / 管理后台）。
- **协作模式**：甲乙方外包项目，我方为**乙方（开发方）**，交付物为 B-D1~B-D8 八类文档 ＋ 源码 ＋ 部署运维接口。

## 5. Analysis

- **架构亮点**：全图**仅 supervisor 一个 LLM 节点**，且**只做意图识别**；路由由 `INTENT_ROUTES` 字典决定 → 从结构上消除「幻觉选工具」风险。
- **风控亮点**：纯规则引擎**不调 LLM**（确定性、可审计、毫秒级、零 token）；一票否决 = **控制流短路**；过敏原在「检索」与「排序」之间做**独立布尔过滤节点**，落到 DB `WHERE`，结构上杜绝「给过敏原菜谱打分后放回」。
- **检索口径**：三路混合召回（覆盖率/文本/向量）＋ 4 维布尔硬过滤（过敏原/忌口/难度/设备）＋ 7 因子加权 + 被过滤明细可重放。
- **降级设计**：风控异常/超时 → `safe_mode_handler` 保守模式，绝不直连模型。
- **短板自陈**：阶段一实际仅 coverage + difficulty 两因子真正生效；默认 `HashEmbeddingProvider` 是字符 bigram 哈希（字面重叠，非语义），`BGEM3Provider` 仍是占位。
- **合规现状**：RL-14 单独同意提前落地；但生成式 AI 备案 / 小程序备案 / 类目资质 / 虚拟支付签约**未启动** —— 全项目唯一**外部不可压缩**的关键路径。
