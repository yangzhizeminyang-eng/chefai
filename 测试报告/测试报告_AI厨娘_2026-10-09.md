## 1. 测试环境说明

| 项目 | 内容 |
|---|---|
| 被测系统 | AI 厨娘・智能烹饪助手（Vue 3 + Element Plus + Pinia + vue-router，Vite 构建） |
| 前端服务 | Vite Dev Server，端口 5173（strictPort 固定），`/v1`、`/api` 代理至后端 |
| 后端服务 | FastAPI，localhost:8000（阶段一接口：ask / recommend / ingredients / inventory / shopping-list / trace / settings / feedback / member 等） |
| 浏览器 | Chromium 内核（Qoder 内置浏览器），视口 1376×712 |
| 数据模式 | 匿名会话（`X-Anonymous-Id: anon_96c2135b0e51`），数据按匿名用户隔离 |
| 测试账号状态 | 免责声明已同意；建档 1 人（测试者，过敏原：花生）；设备：炒锅；烹饪历史 1 条（番茄炒蛋） |

**截图说明**：本次测试环境的内置浏览器视口不可用（`NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`），无法输出位图截图；所有界面证据均以可访问性快照（accessibility snapshot）与 DOM 取值记录，关键结论附原始数据片段。

**覆盖模块**：首页、免责声明门、意见反馈、选择食材、推荐结果、菜谱详情、烹饪模式（步骤/计时器）、家庭档案（成员/设备/饮食目标）、我的冰箱（库存/购物清单）、我的（收藏/历史/拿手菜/营养/会员/设置）、Agent 调度面板、路由兜底。

**未覆盖**：拍照识别食材（无摄像头/图片样本）、语音播报、后端宕机容灾（未中断本地后端）、移动端真机、支付流程（会员「暂不可购」锁定态）。

## 6. 测试总结与建议

### 6.1 总体评价

产品骨架与后端能力**明显好于前端接线质量**：

- **亮点**：① PIPL 敏感信息（过敏原）单独同意的合规设计；② 推荐结果的过滤透明度（被过滤菜谱+原因统计）；③ Agent 调度面板的节点级证据（耗时/token/成本/风控）；④ 临期提醒从库存贯穿到首页；⑤ 空态与免责文案覆盖完整；⑥ 全程控制台 0 error。
- **核心断点**：「问厨娘→拿到推荐」「库存新增」这两条**最高频价值链路在前端断裂或不可用**（H1/H2），而后端对应接口均验证正常——属于典型的「联调缝隙」，修复成本低、收益极高。

### 6.2 修复优先级建议

1. **P0（发版阻断）**
   - H1：`InventoryView` 提交前将位置标签映射为 `fridge/freezer/room/dry` 枚举（LABELS 与 LOCATION_OPTIONS 二选一统一为枚举）。
   - H1b：库存食材下拉改用 `GET /v1/ingredients?q=` 远程搜索（后端已支持），或一次拉全量分类数据。
   - H2：首页「问厨娘」消费 `/v1/ask` 响应——intent=recipe_search 时预选食材并跳 /recommend，chat 类意图就地展示回答。
2. **P1（快速跟进）**
   - M2：后端 hard_filter 接入设备维度 + 档案设备清单补「燃气灶/电磁炉」等灶具枚举。
   - M4：反馈 textarea 加 `maxlength=500` + 前端校验；空内容提交给提示。
   - M6：推荐页「Agent 调度 trace」改为同时暴露 `request_id` 并支持一键跳转 /trace?request_id=。
   - M3：步骤用量提示接入份数缩放；M5 统一营养口径（单份/总量明确标注、消除随机波动）。
3. **P2（体验打磨）**
   - 全局 404 兜底路由；toast 防堆叠去重；已选食材 sessionStorage 持久化；库存位置显示中文化；免责声明去重；字号档位作用域扩大到全局根变量；自定义复选框扩大可点击热区。

### 6.3 遗留风险与后续测试建议

- **未覆盖**：拍照识别（需图片样本与额度）、语音播报、后端宕机/弱网容灾（建议用中断 8000 端口做三态兜底专项）、移动端视口与真机、注销账号与数据导出全链路、会员支付（当前锁定态）。
- **测试数据残留**：本次为验证曾通过 API 以临时匿名用户创建库存条目（id 258/259，归属一次性匿名用户，不影响浏览器账号），并在浏览器匿名用户下保留 鸡蛋（明日到期）/番茄/小葱（已转库存）用于临期与首页提醒验证；如需清理可在「我的冰箱」手动删除，或提供 `DELETE /v1/inventory/{id}` 调用清单。
- **回归重点**：每次修复 H1/H2 后，请重跑 §2.6/§2.2 两个模块及 §2.10 的 Q4 前端载荷比对。
